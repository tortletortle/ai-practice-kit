# 前端训练统一评分标准

每项 0—5 分。评分必须给出截图、行为、代码或测试证据；没有证据的项目标记为 N/A，不得默认满分。

## 评分维度

| 维度 | 0 分 | 3 分 | 5 分 |
|---|---|---|---|
| 需求与产品理解 | 核心目标错误 | 主要任务正确，仍有遗漏 | 用户、场景、任务和边界清晰，设计取舍有依据 |
| 信息架构 | 结构混乱 | 基本可用 | 层级自然，核心流程短且可理解 |
| 视觉辨识度 | 模板感强或粗糙 | 风格基本统一 | 有明确且适合产品的视觉语言 |
| 视觉层级 | 无主次 | 主要层级可识别 | 焦点、节奏、留白和密度控制成熟 |
| 排版 | 难读或不一致 | 可读，少量不一致 | 字体、字号、行高和行长形成稳定系统 |
| 色彩与细节 | 随意或对比不足 | 基本协调 | 角色清晰、克制、状态表达准确 |
| 交互完整性 | 关键控件无效 | 核心流程可用 | 状态、反馈、异常和撤销路径完整 |
| 响应式 | 严重溢出或不可用 | 常见视口可用 | 不同视口均有合理的信息重排 |
| 可访问性 | 键盘或语义严重缺失 | 基础语义和焦点可用 | 键盘、标签、对比度、状态等考虑充分 |
| 工程质量 | 无法运行或大量错误 | 可运行且结构合理 | 可维护、性能合理、错误处理清晰 |
| 设计还原度 | 与确认效果图明显不符 | 主体接近 | 布局、层级、组件和状态高度一致 |
| 证据完整性 | 无真实证据或伪造 | 有部分运行截图和测试 | 效果图、真实截图、测试、commit 可追溯 |

## 评分解释

- 0：缺失、错误或无法使用。
- 1：严重不足，阻断核心体验。
- 2：有部分实现，但存在明显缺陷。
- 3：达到基本可用标准。
- 4：质量较高，仅有少量可改进项。
- 5：成熟、稳定，有充分证据支持。

## 通过门槛

正式通过需同时满足：
- 需求理解、信息架构、交互完整性、响应式和证据完整性均不低于 3 分；
- 总分达到 80%（按有证据的适用维度折算）；
- 核心用户流程实际运行成功；
- 设计效果图和实现截图均已归档；
- 无未解释的阻断级问题；
- 用户已完成本轮审查，或明确授权按客观验收标准结项。

视觉审美最终仍由出题者评审。客观评分不能取代用户对风格和产品气质的判断。

## 缺陷严重度

- P0：核心流程不可用、数据丢失、安全或严重误导。
- P1：主要任务受阻、关键页面不可读、移动端核心功能不可用。
- P2：明显视觉/交互问题，但存在可行绕行方式。
- P3：细节、微交互或非关键一致性问题。

## 评分记录要求

每个分数必须写：
- 证据位置；
- 具体观察；
- 影响；
- 下一步改进；
- 是否纳入通用提示词。
